OpenAI Codex 实战——让AI帮我做PPT和写实验报告OpenAI Codex in Action — Letting AI Make PPTs and Write Lab Reports

2026-05-12 2800 字 572 阅读 约11 分钟

OpenAI Codex是OpenAI推出的CLI+云端编程智能体，支持/goal自主循环执行、并行处理和开源定制。这篇文章记录了我在同一天里用它完成了两项任务：一份18页的技术演讲PPT和一份包含3个完整实验的数据结构实验报告Word文档。

整个过程不是"一键生成"，而是人机协作、反复调试的真实写照——这也是2026年VibeCoding的典型工作方式。

一、实战一：制作2026 VibeCoding工具全景PPT

任务描述

给Codex下达了一个需求：制作一份面向课堂分享的PPT，介绍2026年主流的10款VibeCoding工具。

Codex生成了一个完整的Node.js脚本build-deck.mjs，使用@oai/artifact-tool的presentation-jsx引擎，以JSX声明式语法构建18页幻灯片。

PPT内容结构

PPT十八页内容结构：

  1. 封面 — 标题"2026年主流VibeCoding工具"，列出10款年度焦点工具
  2. 目录 — 五大章节导航：概念定义→生态全景→10款工具→横向对比→选型与未来
  3. 什么是VibeCoding — Karpathy 2024年提出，2026年已演进为多智能体协同的软件工程范式
  4. 生态全景 — 四大阵营：国际巨头、中国本土、独立IDE、生态平台
    5-14. 10款工具逐页介绍 — Claude Code、Trae、Antigravity、OpenAI Codex、Cursor、GitHub Copilot、Windsurf、Devin、Replit AI、通义灵码
  5. 横向对比总结 — 一表看清10款工具的类型、自主能力、中文体验、适合人群和费用模式
  6. 选型决策指南 — 按角色推荐工具组合策略：IDE+CLI+后台智能体"三件套"
    17-18. 未来展望+致谢

踩坑与修复

Codex生成的代码虽然结构完整，但在实际运行中遇到了4个bug，需要逐一排查修复：

Bug 报错信息 原因 修复方案
Grid布局 Grid could not place child rowSpan:2 越界，Grid只定义了2行 改用 columnSpan: 2 跨列
Windows路径 ENOENT: mkdir 'D:\D:\...' URL.pathname 在Win上带前导/ 改用 fileURLToPath(import.meta.url)
内容溢出 column overflowed by 86.8px 4个panel总高度超出可用空间 padding 20→16, gap 10→8, 字号 22→20
Blob API blob.arrayBuffer is not a function 两个API返回不同Blob类型 兼容两种数据获取方式

最终成果

  • 18页幻灯片全部生成
  • output.pptx
  • 18张PNG预览图+Layout JSON

二、实战二：撰写数据结构实验报告Word文档

任务描述

同一次对话中，Codex还帮我完成了另一项任务：从数据结构课程的实验要求中任选三个实验，写出包含实验应用、算法设计、完整C语言代码、实验总结的正式报告，输出为Word文档。

Codex使用Python的python-docx库编写了build_codex_test1.py脚本，生成格式规范的.docx文件。

三个实验概览

实验一：单链表学生信息管理系统

学生成绩管理系统是高校教务中最常见的数据管理场景。使用单链表实现学生信息的增删改查。

核心数据结构：

typedef struct Student {
    char id[12];
    char name[20];
    float score;
    struct Student *next;
} Student;

包含尾插法、查找、插入、删除、排序、输出共6个函数。

实验二：哈夫曼编码与解码系统

哈夫曼编码是数据压缩领域的经典算法，广泛应用于ZIP压缩、JPEG图像编码、MP3音频编码等场景。

核心数据结构：

typedef struct HuffmanNode {
    char ch;
    int freq;
    struct HuffmanNode *left, *right;
} HuffmanNode;

包含最小堆、建树、生成编码、编码文件、解码文件功能。

实验三：校园最短路径导航系统

以校园建筑为结点、道路为边，实现两地之间的最短路径查询与可视化路径输出。

核心数据结构：

#define MAXV 20
typedef struct {
    char name[30];
    int edges[MAXV][MAXV];
    int n;
} CampusGraph;

实现Dijkstra最短路径+路径回溯+路径打印。

文档格式

要素 规格
封面页 标题 + 元信息表
目录页 三个实验的导航
实验结构 实验应用 → 算法设计 → C代码 → 结果说明 → 实验总结
代码验证 gcc -fsyntax-only -std=c99 语法检查通过
排版 微软雅黑标题 + 宋体正文 + Consolas代码，1.5倍行距

三、经验与反思

要点 说明
VibeCoding ≠ 一键生成 AI负责广度（生成框架代码），人负责深度（审查、调试、验证）。正如Karpathy所说："从逐行写代码，转向描述意图、审查生成结果"
技术栈选择关键 PPT用 @oai/artifact-tool JSX（960行但结构清晰），Word用 python-docx（API直观），各有所长
环境差异不容忽视 Win路径处理、库版本API差异、CSS Grid隐式行限制——AI预判不到，需开发者调试能力

总结

这次实战让我深刻体会到：2026年的VibeCoding，本质上是"AI负责广度（快速生成框架和基础代码），人负责深度（审查、调试、优化、验证）"。

Codex的/goal自主循环能力让它在处理这类"生成型"任务时表现出色——定义好输入输出的规格，它就能持续迭代直到完成。而人的价值在于：判断方向是否正确、修复AI的盲区、把关最终质量。

两个项目都在半小时内完成了从需求到交付的全过程，这在传统开发模式下是不可想象的。

OpenAI Codex in Action

OpenAI Codex is a CLI + cloud coding agent by OpenAI. I used it to complete two tasks in one day: an 18-slide technical presentation and a data structures lab report Word document.

Task 1: 2026 VibeCoding Tools PPT

Codex generated a complete Node.js script building 18 slides covering 10 major VibeCoding tools. Encountered 4 bugs: Grid layout rowSpan error, Windows dual-drive-letter path issue, content overflow, and Blob API incompatibility. All fixed through systematic debugging.

Task 2: Data Structures Lab Report

Three experiments: singly linked list student management system, Huffman encoding/decoding, and campus shortest path navigation using Dijkstra's algorithm. Codex used python-docx to generate a professionally formatted Word document with cover page, table of contents, C code with syntax checking, and proper formatting.

Key Takeaways

  1. VibeCoding isn't one-click — it's human-AI collaboration
  2. Tech stack selection is critical
  3. Environment differences matter — AI can't predict all edge cases

Both projects went from requirements to delivery in under 30 minutes each.
