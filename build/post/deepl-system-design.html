软件工程概论实验——DeepL翻译平台系统分析与设计Software Engineering Lab — DeepL Translation Platform System Analysis & Design

2026-05-15 3200 字 256 阅读 约12 分钟

实验概述

本实验是《软件工程概论》课程的综合性实验——系统分析与设计，总计8学时。通过选定DeepL语言翻译平台作为分析对象，运用面向对象的软件工程思想，完成从需求分析到详细设计的完整过程。

实验目的

  1. 理解并掌握面向对象的系统分析方法，包括用例建模、领域建模等技术
  2. 理解并掌握面向对象的系统设计方法，包括架构设计、模块设计、数据库设计等
  3. 掌握ProcessOn、EA、Visio等CASE工具建立系统分析与设计的软件模型
  4. 理解需求分析和设计在软件开发过程中的核心地位和作用
  5. 了解书写软件需求规格说明书和软件设计说明书的相关规范

实验对象：DeepL翻译平台

DeepL是一款基于深度学习神经网络技术（Transformer架构）的高质量在线翻译服务，支持数十种语言互译，并提供文档翻译、网页翻译、API服务、写作辅助（DeepL Write）等多种功能。

核心功能介绍：

  • 文本翻译：支持用户输入文本，选择源语言和目标语言（支持自动语言检测），实现在线实时翻译
  • 文档翻译：支持上传PDF、DOCX、PPTX等格式文档，保持原始格式进行全文翻译
  • API服务：为开发者提供RESTful API接口，支持将DeepL翻译能力集成到第三方应用程序中
  • 词汇表管理：允许用户创建和管理自定义术语词汇表，确保特定术语的翻译一致性
  • DeepL Write：提供AI写作辅助功能，帮助用户改进语法、措辞和风格

本系统开发拟采用增量模型（Incremental Model）结合敏捷开发实践（Scrum框架）的混合过程模型。

实验总结与体会

通过本次实验，我对软件工程中系统分析与设计的方法和技术有了更深入的理解：

  • 系统分析是软件开发的基石——只有充分理解用户需求、梳理业务流程、明确功能边界，才能为后续设计奠定坚实基础
  • 面向对象方法的优势——通过用例图、类图、活动图、顺序图等UML模型，能够从不同视角全面描述系统
  • 分层架构的设计思想——将系统分为表现层、业务逻辑层、服务层和数据访问层，有效实现了关注点分离
  • 数据库设计的关键性——数据库结构设计直接影响到系统的性能和可扩展性
  • 过程模型对项目的影响——DeepL这类AI驱动产品适合增量模型，可以快速验证核心价值
  • 规模估算的实践意义——软件规模估算既是科学也是艺术，实际项目中应综合运用多种方法

Software Engineering Lab — DeepL System Analysis & Design

A comprehensive OO system analysis and design of the DeepL translation platform, totaling 8 class hours.

Key Components

Use Case Modeling: 11 core use cases including text translation, document translation, API access, glossary management, and DeepL Write. Identified 7 actor types from Visitor to System Admin.

Functional Architecture: 6 major modules — Text Translation (core), Document Translation, Writing Assistant (DeepL Write), User Services, API Services, and System Management.

Layered Architecture: Presentation → Business Logic → Service → Data Access, following the Dependency Inversion Principle.

Database Design: MySQL 8.0 + Redis, 5 core tables (t_user, t_translation, t_glossary, t_subscription, t_api_key) with full E-R modeling.

Process Model: Incremental model with Scrum, 6 increments over ~32 weeks.

Size Estimation: ~140,000 LOC (COCOMO II) and ~228 FP (Function Point). Estimated 280 person-months with a 15-person team.

Key Takeaways

System analysis is the foundation of software development. OO methods and UML provide multi-perspective system description. Layered architecture achieves separation of concerns. Database design directly impacts performance and scalability.
